## 1.1 题目

**题目3：智能网约车平台区域实时分布式派单与动态运力调度**

在网约车平台中，核心引擎每秒需要处理数万名乘客的呼叫订单，并将其分发给周边的空载司机。派单不仅要考虑距离（空间邻近度），还要考虑路况（时间邻近度）和司机的历史评分（服务质量）。更难的是，在早高峰时期，某区域内可能订单极多而空车极少（供需失衡），系统需要动态识别出这些热点区域，自动将周边其他区域的空载车辆引导（调度）过来，这需要一种高并发、多维度的时空数据处理框架。本题目要求手工实现一套简化的时空数据流缓存与撮合引擎，模拟网约车平台的派单与调度逻辑。

## 1.2 软件功能

本系统实现了以下功能：

1. **空间索引管理**：将 1000×1000 的虚拟城市划分为 100×100 网格矩阵，每个网格维护一个空闲司机链表，支持 O(1) 坐标定位。

2. **订单生成**：每模拟秒随机产生 5~10 个订单，预设 3 个热点区域使订单生成概率明显更高，用于测试供需失衡。

3. **批量派单**：每模拟秒执行一次，从等待队列取订单，在周边网格搜索候选司机，使用最小堆按撮合代价选出最优匹配。支持基础模式（`Score = gridDistance - rating`）和路况增强模式（`Score = gridDistance × trafficCoef - rating`）。

4. **状态机管理**：司机状态 IDLE→ASSIGNED→SERVING→IDLE 流转，以及 IDLE→REPOSITIONING→IDLE 调度流转；订单状态 WAITING→MATCHED→COMPLETED 或 WAITING→CANCELLED（超时取消）。

5. **供需失衡检测**：每秒统计每个网格 `imbalance = waiting - idle`，超阈值标记为红色警报热点。

6. **动态运力调度**：对警报网格，从周边富余网格调度空闲司机，遵守最低保留量约束，优先从距离近、富余量大的网格调度。

7. **EasyX 可视化**：实时热力图（红=订单多、绿=司机多）、司机/订单点位、调度连线、实时统计看板、滚动日志、交互控制。

8. **交互控制**：暂停/继续、单步、重置、调速（0.5×/1×/2×/5×）、热点开关、撮合模式切换、点击查看网格详情、手动加单/加车。

## 1.3 设计思想

### 1.3.1 分层解耦

系统采用五层架构：数据模型层 → 手工数据结构层 → 城市网格层 → 派单引擎层 → 模拟器层 → UI 层。每层职责单一，层间通过清晰接口通信，便于课程答辩时逐层讲解。

### 1.3.2 手工实现核心数据结构

作为数据结构课程设计，所有核心数据结构（单向链表、循环队列、最小堆、动态数组、循环缓冲区）均手工实现，未使用 STL 容器（`vector`/`list`/`queue`/`priority_queue`/`map` 等）。每个数据结构包含完整的构造析构、增删改查、边界检查和内存释放，并禁用拷贝以避免浅拷贝问题。

### 1.3.3 空间换时间

网格空间索引将 O(n) 的全局搜索降为 O(k) 的局部搜索（k 为半径内候选数），通过"空间划分 + 局部搜索 + 最小堆排序"实现高效派单。

### 1.3.4 时间累计驱动

主循环不使用阻塞式 `Sleep` 控制逻辑，而是通过 `std::chrono` 累计时间判断是否到达下一个 Tick，保证 UI 响应且模拟速度可调。

## 1.4 逻辑结构与物理结构

### 1.4.1 逻辑结构

| 数据结构 | 逻辑结构 | 用途 |
|---------|---------|------|
| 单向链表 | 线性结构 | 网格空闲司机存储 |
| 循环队列 | 线性结构（环形） | 等待订单队列 |
| 最小堆 | 树形结构（完全二叉树） | 撮合候选排序 |
| 动态数组 | 线性结构 | 司机池/订单池 |
| 网格矩阵 | 二维数组 | 城市空间索引 |
| 循环缓冲区 | 线性结构（环形） | 日志存储 |

### 1.4.2 物理结构

| 数据结构 | 物理结构 | 存储特点 |
|---------|---------|---------|
| 单向链表 | 链式存储 | 节点分散，指针连接；节点存 Driver* 指针 |
| 循环队列 | 顺序存储 | 连续数组 Order*[]，头尾指针回绕 |
| 最小堆 | 顺序存储 | 连续数组 Candidate[]，下标映射父子关系 |
| 动态数组 | 顺序存储 | 连续数组 T[]，容量不够时 1.5 倍扩容 |
| 网格矩阵 | 顺序存储 | 二维数组 GridCell cells_[100][100] |
| 循环缓冲区 | 顺序存储 | 固定数组 LogEntry[30] |

**关键设计**：链表节点和队列中存储的是对象指针（`Driver*`/`Order*`），而非对象副本。对象本身由模拟器的 `DynamicArray` 统一管理，析构时统一释放，避免悬空指针和重复释放。

## 2.1 所做的工作

### 2.1.1 需求分析与方案设计

### 2.1.2 手工数据结构实现

实现了 5 种手工数据结构：
- **单向链表**（`SinglyLinkedList.h`）：网格空闲司机存储，头插 O(1)，按编号删除 O(n)，禁用拷贝避免浅拷贝。
- **循环队列**（`CircularQueue.h`）：等待订单队列，留空位区分空满，支持回绕和按编号删除。
- **最小堆**（`MinHeap.h`）：撮合候选排序，三级比较规则（score→rating→id）保证稳定，2 倍扩容。
- **动态数组**（`DynamicArray.h`）：模板类，1.5 倍扩容，带边界检查。
- **循环缓冲区**（`Logger.h`）：固定 30 条日志，满后覆盖最旧。

### 2.1.3 核心算法实现

- **空间索引**（`CityGrid`）：100×100 网格矩阵，O(1) 坐标映射，按半径搜索候选司机。
- **派单引擎**（`DispatchEngine`）：最小堆撮合，支持基础/路况两种模式，统计单次和累计耗时。
- **状态机**（`Simulator`）：司机 4 状态、订单 4 状态的完整流转，含超时取消。
- **热点检测与调度**（`Simulator::detectAndReposition`）：供需差统计、警报标记、最低保留量约束的跨网格调度。

### 2.1.4 图形界面实现

使用 EasyX 实现了完整的可视化界面：热力图（颜色映射供需差）、司机/订单点位、调度连线、实时看板（17 项指标）、滚动日志（分类着色）、9 个交互按钮、鼠标点击网格详情。

### 2.1.5 测试与调试

编写了 10 组自检测试覆盖手工数据结构和核心算法，另有 10 组手动功能测试。修复了调度时 totalIdle 计数不一致的问题（通过统一 `popIdleDriver` 接口）。
