# 设计文档

## 一、总体架构

系统采用分层模块化设计，各层职责清晰分离：

```
┌─────────────────────────────────────────────┐
│              UI 层 (EasyXRenderer)            │  绘制 + 事件处理
├─────────────────────────────────────────────┤
│            模拟器层 (Simulator)               │  订单生成/状态机/调度
├─────────────────────────────────────────────┤
│     派单引擎 (DispatchEngine)                 │  最小堆撮合
├─────────────────────────────────────────────┤
│     城市网格 (CityGrid)                       │  空间索引
├─────────────────────────────────────────────┤
│  手工数据结构层 (SinglyLinkedList /          │  存储 + 基本操作
│    CircularQueue / MinHeap / DynamicArray)   │
├─────────────────────────────────────────────┤
│  数据模型层 (Driver / Order)                  │  结构体定义
└─────────────────────────────────────────────┘
```

**设计原则**：
- 数据结构层只负责存储与基本操作，不包含业务逻辑
- 城市网格层负责坐标映射和空间索引
- 派单引擎只负责撮合算法，不关心订单如何产生
- 模拟器层协调各模块，管理状态机和调度逻辑
- UI 层只负责绘制和输入，不直接实现派单算法

## 二、主要类的职责

### 2.1 数据结构层

| 类 | 职责 |
|----|------|
| `SinglyLinkedList` | 单向链表，网格空闲司机存储。头插 O(1)，按编号删除 O(n) |
| `CircularQueue` | 循环队列，等待订单存储。入队/出队 O(1) |
| `MinHeap` | 最小堆，撮合候选司机排序。插入/弹出 O(log n) |
| `DynamicArray<T>` | 动态数组模板，司机池/订单池等可变长度存储 |

### 2.2 核心引擎层

| 类 | 职责 |
|----|------|
| `CityGrid` | 100×100 网格矩阵，O(1) 坐标定位，网格统计，候选司机搜索 |
| `DispatchEngine` | 对单个订单执行最小堆撮合，统计撮合耗时 |
| `Simulator` | 系统指挥中心：订单生成、状态机推进、批量派单、热点检测、动态调度 |
| `Logger` | 循环缓冲区日志器，保存最近 30 条日志 |

### 2.3 UI 层

| 类 | 职责 |
|----|------|
| `EasyXRenderer` | EasyX 图形界面：热力图、看板、日志、按钮、事件处理 |

## 三、手工数据结构设计

### 3.1 单向链表 (SinglyLinkedList)

```
head -> [Driver* | next] -> [Driver* | next] -> ... -> nullptr
```

- **节点**：`Node { Driver* data; Node* next; }`，只存指针不存对象副本
- **头插法**：新司机加入网格时 O(1) 插入头部
- **按编号删除**：遍历链表找到目标节点，调整前驱指针，O(n)
- **禁用拷贝**：`= delete` 拷贝构造和赋值，避免浅拷贝导致重复释放
- **析构**：逐个 delete 节点，但不 delete Driver 对象（由 Simulator 统一管理）

### 3.2 循环队列 (CircularQueue)

```
data_: [0][1][2][3][4]   capacity=5, 可用容量=4
        ^              ^
       front          rear
```

- **环形结构**：`front_` 指向队首，`rear_` 指向下一个入队位置
- **空满判定**：留一个空位区分空和满。空：`count_==0`；满：`count_==capacity_-1`
- **回绕**：下标通过 `(idx+1) % capacity_` 实现
- **按编号删除**：遍历找到后，后续元素前移，调整 rear 指针

### 3.3 最小堆 (MinHeap)

```
存储数组（0 下标）：
       [0]
      /   \
    [1]   [2]
   /  \   /  \
 [3] [4] [5] [6]

parent(i) = (i-1)/2
left(i)   = 2i+1
right(i)  = 2i+2
```

- **元素**：`Candidate { score, driver, distance, ... }`，保存撮合所需全部信息
- **比较规则**：score 小优先 → score 相同 rating 大优先 → rating 相同 id 小优先（保证稳定）
- **扩容**：容量不够时 2 倍扩容，手动 new/delete + 拷贝
- **上浮/下沉**：标准堆调整操作

### 3.4 动态数组 (DynamicArray<T>)

- **底层**：连续数组 `T* data_`
- **扩容**：1.5 倍扩容，手动 new/delete + 拷贝
- **访问**：O(1) 下标访问，带 `assert` 边界检查
- **删除**：用末尾元素填补，不保证顺序（适用于司机池等不关心顺序的场景）

### 3.5 日志循环缓冲区 (Logger)

- 固定大小数组 `LogEntry entries_[30]`
- `head_` 指向最旧，`count_` 记录当前条数
- 满后覆盖最旧（FIFO 环形覆盖），写入 O(1)

## 四、网格坐标映射

```
城市坐标系：0 ≤ x < 1000, 0 ≤ y < 1000
网格矩阵：100 × 100
网格边长：CELL_SIZE = 1000 / 100 = 10

映射公式（O(1)）：
  row = (int)y / CELL_SIZE
  col = (int)x / CELL_SIZE

边界保护：
  越界坐标夹紧到 [0, CITY_SIZE-1]
  网格下标夹紧到 [0, GRID_COUNT-1]
```

每个网格 `GridCell` 维护：
- `idleDrivers`：空闲司机链表
- `idleDriverCount`：空闲司机数量（冗余计数，避免遍历）
- `waitingOrderCount`：当前等待订单数
- `imbalance`：供需差值 = waiting - idle
- `isHotspot`：是否为订单高发热点
- `isAlert`：是否触发供需失衡警报

## 五、派单流程

每个模拟秒执行一次 `batchDispatch()`：

```
1. 从循环队列取出所有等待订单（暂存到临时数组）
2. 对每个订单：
   a. 调用 DispatchEngine.matchOrder()
   b. matchOrder 内部：
      - 从订单所在网格开始，一圈一圈扩大搜索（最大半径 8）
      - 收集所有空闲司机到 candidates 数组
      - 为每名候选司机计算撮合分数，压入最小堆
      - 弹出堆顶 = 最优匹配
   c. 匹配成功：
      - 从网格链表删除该司机
      - 司机进入 ASSIGNED 状态
      - 订单进入 MATCHED 状态
      - 记录日志
   d. 匹配失败：
      - 订单重新入队，等待下一轮
3. 临时数组中未处理的订单重新入队
```

**为什么先全部取出再逐个处理？**
避免在遍历队列时反复处理同一订单导致死循环。取出后逐个撮合，失败的重新入队，这一轮不再处理。

## 六、最小堆撮合过程

### 撮合代价公式

**基础模式**：
```
Score = gridDistance - rating
     = (pixelDistance / CELL_SIZE) - rating
```

**路况增强模式**：
```
Score = gridDistance × trafficCoef - rating
     = (pixelDistance / CELL_SIZE) × trafficCoef - rating
```

其中 `trafficCoef` 根据网格类型：
- 普通网格：1.0
- 热点网格：1.5
- 警报网格：2.0

### 比较规则（保证稳定）

```
1. score 小的优先（代价低）
2. score 相同时，rating 大的优先（服务好）
3. rating 也相同时，id 小的优先（编号小）
```

第 2、3 条规则保证相同分数下结果稳定可复现。

### 示例

订单在网格(50,50)，有3名候选司机：
- 司机A：距离 3 格，评分 4.5 → score = 3 - 4.5 = -1.5
- 司机B：距离 5 格，评分 4.8 → score = 5 - 4.8 = 0.2
- 司机C：距离 3 格，评分 4.0 → score = 3 - 4.0 = -1.0

堆顶 = 最小 score = 司机A (-1.5)，匹配成功。

## 七、状态机

### 司机状态机

```
                 匹配成功
  IDLE ──────────────────→ ASSIGNED
   ↑                         │
   │                         │ ASSIGNED_DURATION (3秒)
   │ 服务完成                 ↓
   │ (移动到新位置)    SERVING
   │                         │
   │                         │ SERVING_DURATION (8秒)
   │                         ↓
   └─────────────────────────┘
   
  IDLE ──被调度──→ REPOSITIONING ──到达热点──→ IDLE
                    (5秒)           (修改坐标)
```

### 订单状态机

```
  WAITING ──匹配成功──→ MATCHED ──服务完成──→ COMPLETED
    │
    │ 等待 > 15秒
    ↓
  CANCELLED
```

## 八、热点检测与车辆调度流程

### 8.1 供需失衡检测

每个模拟秒执行 `updateImbalance()`：

```
对每个网格(r,c)：
  imbalance = waitingOrderCount - idleDriverCount
  if imbalance > IMBALANCE_THRESHOLD (3):
    标记为警报 (isAlert = true)
```

### 8.2 动态调度

对每个警报网格，搜索周边半径 1~3 的网格：

```
1. 收集所有"富余"网格（idle > MIN_RESERVE_DRIVERS=2）
2. 按距离近、富余量大排序
3. 依次从来源网格取出空闲司机：
   a. popIdleDriver() 从来源网格链表摘除
   b. 司机进入 REPOSITIONING 状态，记录目标网格
   c. remainTime = 5 秒
4. 到达后（remainTime 归零）：
   a. 修改司机坐标到目标网格中心
   b. 重新加入目标网格空闲链表
   c. 状态回到 IDLE
```

**约束**：
- 来源网格司机数必须 > `MIN_RESERVE_DRIVERS`（最低保留 2 名）
- 每秒最多调度 `MAX_REPOSITION_PER_TICK`（10）名司机
- 警报网格不作为来源网格

## 九、时间复杂度和空间复杂度分析

### 时间复杂度

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 坐标→网格映射 | O(1) | 整数除法 |
| 链表头插 | O(1) | pushFront |
| 链表按编号删除 | O(n) | n 为该网格司机数 |
| 队列入队/出队 | O(1) | 循环队列 |
| 堆插入 | O(log k) | k 为候选司机数 |
| 堆弹出 | O(log k) | |
| 单次派单搜索 | O(k log k) | k 为搜索半径内候选数 |
| 批量派单(每秒) | O(m × k log k) | m 为订单数 |
| 供需统计 | O(G) | G=10000 个网格 |
| 调度搜索 | O(G_alert × R²) | R 为搜索半径 |

### 空间复杂度

| 结构 | 空间 | 说明 |
|------|------|------|
| 网格矩阵 | O(G) | G = 100×100 = 10000 个 GridCell |
| 司机池 | O(D) | D = 初始100 + 手动添加 |
| 订单池 | O(O_total) | 累计订单数 |
| 等待队列 | O(O_waiting) | 当前等待订单 |
| 最小堆 | O(k) | k 为单次搜索候选数 |
| 日志缓冲 | O(MAX_LOG_LINES) | 固定 30 |

总体空间复杂度：O(G + D + O_total)，其中 G=10000 为网格数，D 和 O_total 随模拟时间增长。
